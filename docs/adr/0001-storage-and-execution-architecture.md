# 로컬 추적 + 구글 드라이브 기반 클라우드 저장/실행 구조

노트북 활동(스크린타임)은 노트북이 켜져 있을 때만 관측할 수 있지만, 정기 리포트와 마감일 알림은 노트북이 꺼져 있어도 정해진 시점에 발송되어야 한다는 요구사항이 있었다(A6, A20). 이를 위해 활동 추적만 로컬 에이전트가 담당하고, 나머지(성과/KPI 데이터 저장, 리포트 생성, 메일 발송)는 이미 케이트님이 신뢰하고 쓰고 있는 구글 드라이브의 "KPI_tracker" 폴더(A23)와 예약 클라우드 작업으로 처리하기로 했다. 순수 로컬 전용 구조였다면 설정은 더 간단했겠지만 노트북이 꺼진 동안 리포트가 밀리는 문제를 피할 수 없었고, 순수 클라우드 전용 구조는 애초에 스크린타임 자체를 관측할 수 없어 불가능했다.
